# Web Auth Settings Key Editor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and deploy the approved device Web control flow with PIN-first authentication, Settings, Chinese action labels, captured HID chords, and key-purpose summaries.

**Architecture:** Keep the existing ESP-IDF HTTPS server and profile JSON contract. Add one authenticated PIN update API and rewrite the small embedded SPA without adding framework dependencies.

**Tech Stack:** ESP-IDF 5.5.4 C++20 firmware, cJSON, NVS, static HTML/CSS/JS generated by `scripts/build_web_assets.py`, Python pytest, CMake host tests.

## Global Constraints

- Current product remains Cardputer Codex Companion.
- Web PIN is exactly 8 numeric digits.
- Wi‑Fi password is write-only and never returned by API.
- Profile JSON action enum values remain unchanged: `passthrough`, `hid_chord`, `text_utf8`, `input_sequence`, `device_action`, `codex_action`, `disabled`.
- No cloud service or external production server is involved; deployment means building the private full firmware image and flashing the connected Cardputer at `0x0`.
