# Web 键位结果反馈与登录页调整设计

## 目标

优化 Cardputer Codex Companion 设备端 Web 控制台的键位发布反馈与登录体验：

- 键位修改成功或失败后使用页面内结果窗口反馈；
- 成功窗口自动关闭，失败窗口保留到用户确认；
- 登录 PIN 使用掩码输入；
- 修正 PIN 输入框与登录按钮间距；
- 使用用户指定的登录标题与说明文本。

## 范围

本次只修改设备端静态 Web 资源、相应回归测试、生成的固件资源和固件版本。Profile API、PIN 鉴权协议、Wi-Fi API、BLE HID、Mac Companion 和设备显示逻辑保持不变。

“键位修改”包含：

- 在键位编辑器中点击“保存并发布”；
- 点击“恢复直通”。

## 登录页

登录页使用以下固定内容：

- 标题：`Codex Companion Login`
- 说明：`请输入设备PIN码进行鉴权`
- PIN 标签：`设备 PIN`
- 登录按钮：`进入控制台`

`login-pin` 使用 `type="password"`、数字输入模式、八位长度和八位数字校验。输入内容始终以浏览器密码掩码显示，不在页面文本中回显。

`pin-form` 使用独立的纵向 flex 布局，在 PIN 字段和按钮之间保留明确间距，并在说明文本下增加顶部间距。样式只作用于登录表单，不改变 Settings 表单。

## 页面内结果窗口

新增独立 `result-modal`，层级高于键位编辑弹窗，使用 `role="alertdialog"`、`aria-modal="true"`、标题和正文关联属性。

结果窗口有两种状态：

### 成功

- 标题：`修改成功`
- 正文：说明当前键位配置已发布到设备；
- 使用成功色；
- 显示后约 1.5 秒自动关闭；
- 用户也可主动点击“确定”关闭。

### 失败

- 标题：`修改失败`
- 正文：包含经过文本节点安全渲染的 API 或解析错误；
- 使用错误色；
- 不自动关闭；
- 用户点击“确定”后回到仍保持打开的键位编辑器继续修改。

切换结果状态前必须清除已有自动关闭计时器，避免先前的成功计时器关闭后续失败窗口。

## 键位保存数据流

### 保存并发布

1. 保存当前绑定副本。
2. 从编辑器读取新动作。
3. 调用现有 Profile `PUT` 发布。
4. 成功时刷新 Profile 和键帽，关闭键位编辑器并显示成功窗口。
5. 失败时恢复页面内旧绑定，保持键位编辑器打开并显示失败窗口。
6. 请求期间禁用保存按钮，结束后恢复。

### 恢复直通

1. 保存当前绑定副本。
2. 将当前绑定临时改为 `passthrough`。
3. 调用同一个 Profile `PUT` 发布。
4. 成功时刷新键帽，关闭键位编辑器并显示成功窗口。
5. 失败时恢复旧绑定，保持编辑器打开并显示失败窗口。
6. 请求期间禁用“恢复直通”和保存按钮，防止并发提交。

恢复直通不再只修改浏览器内存。

## 安全与兼容性

- PIN 仍只通过 `X-Cardputer-Pairing` 请求头发送。
- 结果正文使用 `textContent`，不使用 `innerHTML` 插入错误内容。
- Profile JSON、动作枚举、API 路由和 NVS 格式不变。
- 不新增第三方 JavaScript 依赖。
- 现有中文、组合键和字符串编辑功能保持兼容。

## 验证

自动化验证覆盖：

- 登录标题和说明文本精确匹配；
- `login-pin` 是密码输入并保留八位数字约束；
- 登录表单具有独立间距样式；
- 结果窗口具有页面内、可访问的 dialog 结构；
- 保存与恢复直通均调用 Profile 发布路径；
- 成功使用自动关闭结果状态；
- 失败回滚绑定并使用手动关闭结果状态；
- 生成的 `web_assets.hpp` 与源码一致；
- JavaScript 语法检查、Python 测试、普通/消毒器 host tests 和 ESP-IDF 产品构建通过。

部署使用 app-only 刷写到 `0x20000`，保留设备现有 PIN、Wi-Fi、Profile 和 BLE bond。刷写后通过 HTTPS 页面内容与状态 API 确认新版本和运行状态。
